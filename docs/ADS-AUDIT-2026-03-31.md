# Ads System — Full Audit Report

> **Date:** 2026-03-31  
> **Auditor:** Dr. Strange (Coding Lead)  
> **Method:** Live browser testing + DB queries + code review  

---

## Executive Summary

The ads system has the right pieces but they're fragmented, partially broken, and showing inconsistent data. There are 5 pages, 18 API endpoints, 2 generation engines (one legacy), and data integrity issues that mean the numbers Grace sees may not match reality.

**Critical issues:**
1. ROAS numbers wildly inflated due to broken ad_creatives deduplication
2. 22 ads have ₱0 spend + "unknown" status but exist in the system
3. Two generation engines (legacy factory + creative tree V2) both active
4. Intelligence layer disconnected from the main page
5. Daily performance data is 5 days stale

## Data Integrity Issues

### Issue 1: Phantom Performance Data on Engagement Ads

**This is the biggest problem.** All 50 `meta_ad_id` values are unique — no duplicates. BUT: 4 different "New Engagement Ad" variants (different ad IDs, different campaigns, different body text) all show **identical ₱73,705 spend and 8.09x ROAS** — and they have **ZERO daily performance rows**.

These 4 ads are ENGAGEMENT objective campaigns. The Meta sync assigned them spend/ROAS during the creative sync, but the data appears to be account-level aggregates incorrectly attributed per-ad, not actual per-ad spend.

**Impact:**
- 4 ads × ₱73,705 = ₱294,820 in phantom spend inflating totals
- These 4 ads show as "winning" with 8x ROAS — but we don't actually have their real performance
- "224x ROAS for Pain Point" on the create page comes from one of these phantom numbers
- The strategy map shows winning cells that may not be real

**11 ads total have zero daily rows** but some have denormalized spend/ROAS. The denormalized fields on `ad_creatives` can't be trusted when daily data is missing.

**Root cause:** The `/api/ads/creatives/sync` endpoint aggregates from `ad_performance` daily rows → ad_creatives. But for ads with no daily rows, Meta's ad-level insights API may be returning campaign-level numbers. Need to investigate the sync code.

### Issue 2: 22 "Unknown" Status Ads — ₱0 Spend

22 ads have `ad_status = 'unknown'` and `total_spend = 0`. These were classified by Gemini (all have `classified_at`) but have no performance data. They exist as ad creatives in Meta but either:
- Never spent money (draft/paused)
- Their daily performance wasn't synced

They shouldn't show as "working" but they inflate the ad count.

### Issue 3: Daily Performance Data Stale

Last `ad_performance` row: 2026-03-26 (5 days old). The "Last 7 days" view on /ads is showing stale data. No cron is running to keep this fresh.

### Issue 4: No `performance_updated_at` on Any Creative

The `performance_updated_at` column is NULL for all 50 ad_creatives. The sync flow either doesn't set it or it was never triggered after the initial classification.

### Issue 5: Two Generation Engines

| Engine | Tables | Endpoints | Status |
|--------|--------|-----------|--------|
| Legacy Factory | ad_factory_batches (8), ad_factory_variants (24) | /api/ads/factory/* | Still active, /ads/weekly uses it |
| Creative Tree V2 | creative_concepts (8), creative_hooks (19), creative_executions (39) | /api/ads/creative-tree | Primary, /ads/create uses it |

Both have generated content. Neither knows about the other. The weekly planner calls the legacy factory while the create page calls V2.

## Fragmentation Map

```
/ads (audit)  ←→  /api/ads/metrics (daily data, CORRECT)
                   /api/ads/creatives

/ads/strategy ←→  /api/ads/intelligence/map (denorm data, WRONG ROAS)

/ads/create   ←→  /api/ads/angle-coverage (denorm data, WRONG counts)
                   /api/ads/weekly-plan
                   /api/ads/creative-tree (V2 engine)

/ads/weekly   ←→  /api/ads/factory/batch (LEGACY engine, different from V2)
                   /api/ads/factory/generate (LEGACY)

/ads/competitors ←→ /api/ads/competitors
                    /api/ads/sentiment
```

**The problem:** Three different data interpretations depending on which page you're on:
1. `/ads` → daily aggregated data (correct but stale)
2. `/ads/strategy` + `/ads/create` → denormalized ad_creatives data (duplicated, inflated)  
3. `/ads/weekly` → legacy factory (completely separate generation engine)

---

## Recommendations

### P0 — Fix Before Anything Else
1. **Fix ad_creatives deduplication** — deduplicate by meta_ad_id. One row per unique ad, aggregate spend across campaigns.
2. **Sync daily data** — run the Meta sync to get current ad_performance rows.
3. **Kill legacy factory** — remove /ads/weekly page (or rewire to V2), deprecate /api/ads/factory/* endpoints.

### P1 — Consolidate Data Sources
4. **Strategy map and create page should use daily data** — same source as /ads audit.
5. **Remove intelligence map's own ROAS calculation** — delegate to /api/ads/metrics.

### P2 — Build the Missing Intelligence Layer
6. **Surface recommendations on /ads** — "What to do next" section above the campaign tree.
7. **Link ads to actions** — "This ad is tired → Make New Version" inline.
8. **Connect competitors to create** — "Competitors use comparison → Create Comparison Ads" button.

### P3 — Clean Up
9. **Delete legacy factory tables** (ad_factory_batches, ad_factory_variants) or archive.
10. **Remove redundant API endpoints** (/api/ads/sync, /api/ads/performance, /api/ads/factory/*).
11. **Set up daily sync cron** for ad_performance + creative status refresh.
